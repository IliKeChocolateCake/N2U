1. ✧･ﾟ: *✧･ﾟ:* PROJECT OVERVIEW ✧･ﾟ: *✧･ﾟ:*

 ✦ • •  N2U Application Overview ✦ • •

 The N2U App is a member rewards mobile application that provides voucher management, digital wallet functionality, transaction tracking,
 and notification support to enhance user engagement and system transparency.

 ✦ • • Core Modules & Key Features ✦ • •


    ✧ Voucher Management

       ⋆｡°✩ Display active, used, and expired vouchers

       ⋆｡°✩ Voucher redemption using member points

       ⋆｡°✩ Voucher code copy functionality for checkout usage


    ✧ Wallet Management

       ⋆｡°✩ Real-time wallet balance display

       ⋆｡°✩ Support for multiple wallet types (e.g. Dine-in Wallet, Cash Wallet)


    ✧ Top-Up

       ⋆｡°✩ Submit wallet top-up requests

       ⋆｡°✩ Top-up requests remain pending until approved

       ⋆｡°✩ Wallet balance updates upon approval

       ⋆｡°✩ User notification on top-up status changes


    ✧ Withdrawal

       ⋆｡°✩ Submit wallet withdrawal requests

       ⋆｡°✩ Withdrawal requests processed after approval

       ⋆｡°✩ Funds deducted from cash wallet upon approval

       ⋆｡°✩ User notification on withdrawal status changes


     ✧ Wallet Transaction History

       ⋆｡°✩ View transaction records for:

           ☆彡 Top-ups

           ☆彡 Withdrawals

           ☆彡 Wallet usage

           ☆彡 Chronological transaction listing for tracking and auditing


      ✧ Order History

       ⋆｡°✩ View past orders and order details

       ⋆｡°✩ Track voucher usage per order


      ✧ Notifications

        ⋆｡°✩ Receive system, transactional, and announcement notifications

        ⋆｡°✩ Unread notification count tracking

        ⋆｡°✩ Notification status management (read / unread)

        ⋆｡°✩ Local storage support for notification persistence


       ✧ Member Account

         ⋆｡°✩ Secure authentication and session handling

         ⋆｡°✩ Member profile information display


✦ • • Tech Stack ✦ • •

     ✧ Framework: Flutter

     ✧ State Management:

            1️⃣ setState() – Widget / UI State

                ⋆｡°✩ Handles local UI updates, like:

                ⋆｡°✩ Active tab selection (activeTab)

                ⋆｡°✩ Loading indicators

                ⋆｡°✩ Temporary form input changes

                ⋆｡°✩ List updates after user actions (mark read, delete, refresh)

                ⋆｡°✩ Short-lived state that resets when leaving the widget


            2️⃣ Provider – Shared / Global State

                ⋆｡°✩ Manages app-wide data, such as:

                ⋆｡°✩ Auth / user session

                ⋆｡°✩ Language / localization

                ⋆｡°✩ Unread notification counts

                ⋆｡°✩ Allows multiple screens to read/update the same state


            3️⃣ Local Persistence (SQLite)

                ⋆｡°✩ Notifications stored in SQLite (NotificationDatabase)

                ⋆｡°✩ DB acts as source of truth for:

                ⋆｡°✩ Unread/read status

                ⋆｡°✩ Notification history

                ⋆｡°✩ UI reflects DB changes for offline access and consistency


            4️⃣ Remote State (REST API)

                ⋆｡°✩ App interacts with REST endpoints for:

                ⋆｡°✩ Vouchers

                ⋆｡°✩ Wallet balances, top-ups, withdrawals

                ⋆｡°✩ Orders / order history

                ⋆｡°✩Member profile

            Flow:

                ⋆｡°✩ REST API → Response → setState / Provider → UI


            No heavy caching layer, relies on controlled fetch + refresh


     ✧ Backend: REST API

7. ✧･ﾟ: *✧･ﾟ:* USAGE ✧･ﾟ: *✧･ﾟ:*

✦ • • Application Usage Flow ✦ • •

    This section describes the typical user flow and interaction patterns within the N2U mobile application.

        ✧ App Launch & Session Handling

            ⋆｡°✩ On app startup, the application checks for an existing user session using SharedPreferences.

            ⋆｡°✩ If a valid authentication token exists and Remember Me was enabled, the user is automatically directed to the main member area.

            ⋆｡°✩ If no valid session is found, the user is redirected to the login / sign-up screen.


        ✧ Authentication Flow

            ⋆｡°✩ Users may log in using their registered credentials.

            ⋆｡°✩ Successful login stores session-related data locally to enable persistent login.

            ⋆｡°✩ Logout clears stored session data and returns the user to the authentication screen.


        ✧ Navigation Behavior

            ⋆｡°✩ Navigation between screens is handled using Navigator.push, allowing pages to be stacked.

            ⋆｡°✩ This preserves navigation history so the system back button navigates to the previous screen instead of closing the app.

            ⋆｡°✩ Core pages such as Login, Profile, Wallet, Vouchers, and Settings are accessed through standard route navigation.


        ✧ Back Button Behavior

            ⋆｡°✩ The Android system back button pops the current route and returns the user to the previous page.

            ⋆｡°✩ This ensures predictable navigation and prevents unintended app exits during normal usage.

            ⋆｡°✩ The app exits only when the root screen is reached and no further routes remain in the navigation stack.


        ✧ Member Features Usage

            ⋆｡°✩ Once logged in, users can:

            ⋆｡°✩ View and manage vouchers (active, used, expired)

            ⋆｡°✩ Redeem vouchers using reward points

            ⋆｡°✩ Copy voucher codes for checkout usage

            ⋆｡°✩ View wallet balances and transaction history

            ⋆｡°✩ Submit top-up and withdrawal requests

            ⋆｡°✩ Track reward points and redemption history

            ⋆｡°✩ View order history and voucher usage per order

            ⋆｡°✩ Receive and manage system notifications


        ✧ Localization Usage

            ⋆｡°✩ The application supports multiple languages (English, Chinese, Malay).

            ⋆｡°✩ Language preference is stored locally and restored on app restart.

            ⋆｡°✩ All user-facing strings are localized using easy_localization and .tr().

        ✧ Notification Usage

            ⋆｡°✩ Notifications are received via OneSignal.

            ⋆｡°✩ Notifications are persisted locally using SQLite for offline access.

            ⋆｡°✩ Users can mark notifications as read or delete them.

            ⋆｡°✩ Unread notification counts are reflected in the UI.

    ✦ • • Notes ✦ • •

        ⋆｡°✩ Network connectivity is required for API-based features.

        ⋆｡°✩ Some actions (top-up, withdrawal) depend on backend approval before reflecting changes.

        ⋆｡°✩ UI state updates are handled through a combination of setState, Provider, and local persistence.

9. ✧･ﾟ: *✧･ﾟ:* TROUBLESHOOT ✧･ﾟ: *✧･ﾟ:*


    ✧ App Closes When Pressing Back Button

       Cause:

        The current screen is the root route of the navigation stack.

       Solution:

        Ensure pages are navigated using Navigator.push instead of Navigator.pushReplacement when back navigation is required.

        Verify that the home screen is not unintentionally replacing the route stack.



    ✧ User Is Not Auto-Logged In

       Cause:

        Authentication token is missing, expired, or Remember Me was not enabled.

        SharedPreferences data was cleared.

       Solution:

        Confirm that auth_token and remember_me values are saved after login.

        Verify token validity before navigation.

        Avoid clearing preferences unless explicitly logging out.


    ✧ App Does Not Return to Home After Background Resume

       Cause:

        App lifecycle state is not being observed.

       Solution:

        Ensure WidgetsBindingObserver is implemented on the root page.

        Handle AppLifecycleState.resumed to reset navigation state if required.



    ✧ Localization Text Not Updating

        Cause:

          Missing translation key or .tr() not applied.

          Language preference not saved.

        Solution:

          Confirm translation keys exist in en.json, ms.json, and zh.json.

          Wrap user-visible strings with .tr().

          Verify EasyLocalization initialization in main.dart.


    ✧ Notification Not Appearing

        Cause:

          Notification permission not granted.

          OneSignal not initialized correctly.

        Solution:

          Confirm notification permission is granted on the device.

          Verify OneSignal App ID is correctly configured.

          Check OneSignal login is triggered after user authentication.



    ✧ Voucher List Is Empty

        Cause:

          No available vouchers or API returned an empty response.

          Network connectivity issue.

        Solution:

          Confirm voucher availability from backend.

          Check API response logs.

          Ensure internet connection is active.


    ✧ App Displays Wrong Language on Restart

        Cause:

          Saved language preference not loaded before app start.

        Solution:

          Ensure language is retrieved from SharedPreferences before calling runApp.

          Use startLocale in EasyLocalization.


    ✧ Debug Logs Not Appearing

        Cause:

          Release mode build suppresses logs.

        Solution:

          Use debug mode during development.

          Replace print with debugPrint for better visibility.



✦ • • General Tips ✦ • •

Always test authentication flows with both Remember Me enabled and disabled.

Clear app data if unexpected behavior persists.

Use physical devices when testing notifications and background behavior.

  - App closes/exits completely when user presses back button
  - Instead of returning to home screen, app terminates
  - Back navigation doesn't work as expected in nested screens
  - Users lose their place in the app flow
Cause:
  - Using Navigator.pushReplacement() instead of Navigator.push() throughout the app
  - pushReplacement() removes previous screen from navigation stack
  - No screens left in stack for back button to navigate to
  - When stack is empty, OS defaults to closing the app
Solution:
  - Replace Navigator.pushReplacement() with Navigator.push() for detail screens, settings, profile pages, etc.
  - Keep pushReplacement() ONLY for authentication flows (Login → Home, Logout → Login)
  - Use IDE's Find & Replace to bulk update:

   Find: Navigator.pushReplacement
   Replace: Navigator.push
   Review each occurrence before replacing

  - Alternative: Use Navigator.pop() to explicitly go back to previous screen
Notes:
  - Test back button behavior on all screens after implementing fix
  - Navigator.push() = Adds screen to stack (allows back navigation)
  - Navigator.pushReplacement() = Replaces current screen (no back navigation)

Problem:   Remember Me feature not persisting login sessions.
Platform:: Android / IOS

    - Users logged out after closing app
    - "Remember Me" toggle checked but doesn't work
    - Auto-login not triggered on app restart
    - Credentials not saved despite successful login

    - No check for saved credentials in login screen initState()
    - Auto-login logic not implemented properly
    - Token cleared when app killed
Solution:

    - Save credentials securely when "Remember Me" is checked
    - Check for saved credentials in initState() of login screen
    - Auto-login if valid token + credentials found
    - Clear credentials when "Remember Me" unchecked
Notes:
    - flutter_secure_storage uses Keychain (iOS) and KeyStore (Android)
    - Never store passwords in SharedPreferences (insecure)
    - Clear credentials on logout based on user choice
    - Add delay before auto-login: Future.delayed(Duration(milliseconds: 500))
    - Consider token refresh instead of storing password
    - Comply with security best practices and regulations
